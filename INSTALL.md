# Установка Workshop Starter v0.2.12

Один пакет для Windows и macOS, для Codex и Claude Code. Пути относительны папке проекта.

## Сценарий А: новый проект

Создайте пустую папку проекта и откройте её в агенте как локальный проект. Режим: Claude Code — Auto; Codex — доверие к папке и Approve for me. Затем отправьте:

```text
Установи Workshop Starter в эту папку с GitHub:
скачай https://github.com/ilya0013/workshop-starter/releases/latest/download/workshop-starter.zip,
распакуй во временную папку и перенеси содержимое папки workshop-starter
прямо сюда командой, которая берёт и файлы с точкой (в bash/zsh: cp -R <папка>/. .),
и сверь со списком файлов в архиве — .agents, .claude, .codex должны быть на месте.
Если здесь уже есть файлы — ничего не перезаписывай, покажи совпадения и спроси.
Проверь, что AGENTS.md лежит в корне и все файлы пакета на месте; временные файлы удали.
Затем прочитай правила по INSTALL.md и дай короткий отчёт об установке.
Глобальные настройки не меняй.
```

В Codex после отчёта начните новый чат в этой же папке.

## Сценарий Б: есть свой проект или настройки

Ничего не распаковывайте поверх существующих файлов. Откройте свой проект и отправьте:

```text
Скачай Workshop Starter с https://github.com/ilya0013/workshop-starter/releases/latest/download/workshop-starter.zip
во временную папку вне проекта и сравни его с правилами и настройками текущего проекта.
Пока ничего не меняй. Предложи минимальное объединение:
что сохранить, что добавить и какие конфликты решить.
Сохрани код, память проекта и ограничения безопасности.
Глобальные настройки не меняй. Покажи конкретные правки для согласования.
```

## Порядок для агента

1. Пакет по ссылке скачивай и распаковывай во временную папку вне проекта. В сценарии А переноси в проект содержимое папки `workshop-starter` командой, которая берёт и файлы с точкой (в bash/zsh — `cp -R <папка>/. .`; `mv *` их пропускает), и сверяй со списком файлов архива; временные файлы потом удали. В сценарии Б в проект ничего не переноси до согласия пользователя. Проверь, что в корне открытой папки есть все 17 файлов пакета, включая скрытые `.agents`, `.claude`, `.codex`, `.gitattributes`. Если `.codex/` появился в уже открытой папке Codex, предложи начать новый чат — иначе его config и rules не действуют.
2. В сценарии Б ничего не перезаписывай: покажи план объединения, сохрани код, память, более строгие ограничения и правила Git; правь только после согласия, с возможностью восстановления.
3. Не меняй глобальные настройки, не устанавливай программы, не создавай Git и не публикуй в рамках установки.
4. Прочитай `AGENTS.md`, `docs/PRODUCT.md`, `PLANS.md`, `docs/HANDOFF.md` (в Claude Code также `CLAUDE.md`) и примени `workshop-copilot`; если skill не виден — прочитай его `SKILL.md` и скажи об этом.
5. Отчитайся в четыре строки: папка и состав, где корень Git (Git нет / эта папка / выше); правила и skill; известный режим разрешений и конфликты (чего не знаешь — так и скажи); что нужно от пользователя или первый вопрос о задаче.
   Если открыта не папка проекта, а Рабочий стол, домашняя папка, «Документы» или «Загрузки», или корень Git выше папки — перед отчётом отдельной фразой предупреди по `AGENTS.md` → «Git — только в папке проекта».
6. Помоги сформулировать задачу. При пустом `docs/PRODUCT.md` не придумывай продукт и стек; до согласования приложение не создавай.
